Step-by-Step Guide in Cisco Packet Tracer
File Setup:

Open Cisco Packet Tracer
Go to File > Save As and immediately save it as Smart_College_WiFi_Day1.pkt - so you don't lose progress.
Step 1: Place Devices
On the bottom panel, go to Network Devices.

One Managed Switch: Click on Switches > 2960 - Drag a 2960 switch to the center of your workspace. This is your managed Layer 2 switch. Name it later as College-Core-SW.
One Router: Click on Routers > 2911 - Drag a 2911 router above the switch. The 2911 is better for VLAN trunking than 2811.
Four PCs: Click on End Devices > End Devices - Drag 4 PCs below the switch. These are your 4 user groups. After placing, click on each PC and rename them in the Display Name:
PC0 -> Admin-Dept
PC1 -> Faculty-Group
PC2 -> Student-Group
PC3 -> Guest-IoT
One Server (Optional but Recommended): Click on End Devices > End Devices -> Drag a Server and place it to the side of the switch. Name it College-Server. This will later be your DHCP / Web server.
Step 2: Connect Devices - This is important

Click on the lightning bolt Connections > Copper Straight-Through (solid black line).

Connect PCs to Switch:
Admin-Dept (FastEthernet0) -> Switch (FastEthernet0/1)
Faculty-Group (FastEthernet0) -> Switch (FastEthernet0/2)
Student-Group (FastEthernet0) -> Switch (FastEthernet0/3)
Guest-IoT (FastEthernet0) -> Switch (FastEthernet0/4)
Connect Switch to Router:
Switch (GigabitEthernet0/1) -> Router (GigabitEthernet0/0) - Use Gigabit for trunk later.
Connect Server to Switch (if you added):
College-Server (FastEthernet0) -> Switch (FastEthernet0/5)
After connecting, wait 30 seconds. The dots on the links should turn green. If they stay red/orange, you used the wrong cable type. Delete and try Copper Cross-Over or auto-detect (Connections > Automatically Choose Connection Type).

Step 3: Arrange & Label for Submission

Go to top bar, click Place Note and label your topology.
Select all devices, right-click > Inspect to add notes.
Go to Options > Preferences > Always Show Port Labels - Enable this so your teacher can see the interfaces.
Your final Day 1 layout should look like this: 4 PCs at bottom, Switch in middle, Router on top, Server on side.
Step 4: Save Final
File > Save - Verify file name is Smart_College_WiFi_Day1.pkt

VLAN 10 - Admin, VLAN 20 - Faculty, VLAN 30 - Students, VLAN 40 - Guests

How to Share Your .pkt File So Others Can Edit?
Packet Tracer does NOT have Google Docs style real-time co-editing. A .pkt file is offline. You have to share the file itself. Here is how to make it editable via a link:

Best Method: Google Drive (Recommended for colleges)

Go to drive.google.com and upload Smart_College_WiFi_Day1.pkt
Right-click on the file > Share > Share
Under General Access, change from Restricted to Anyone with the link
On the right side, change Viewer to Editor
Click Copy Link and send it on WhatsApp / Teams. Anyone with the link can download, make changes, and re-upload.
Other Methods:

OneDrive / Dropbox: Same process - Upload > Create Share Link > Allow Editing.
GitHub: If your team uses Git, create a new repository and upload the .pkt file. Your friends can commit changes.
What NOT to do: Don't send it via email attachment if you want collaboration - you'll end up with 5 different versions like Smart_College_WiFi_Day1_final_final2.pkt
To collaborate without confusion:

One person edits at a time
After editing, rename with version: Smart_College_WiFi_Day2_VLANs_YourName.pkt and re-upload to the same Drive folder.

Task 3: Configure the router and trunk link (60 minutes)
Use a router-on-a-stick design if your selected Packet Tracer router supports it.

The general approach is:
1. Configure the switch port connecting to the router as a trunk.
2. Configure one router subinterface for each VLAN.
3. Assign each subinterface the corresponding gateway address.
4. Configure the appropriate 802.1Q VLAN encapsulation.
5. Enable the physical router interface.
Learn why a trunk link is necessary: it carries frames for multiple VLANs between the switch and the router.

Why trunk is necessary?

Perfect — that's actually progress! You flipped from only ICMP to only ARP. Now you need both.

This happens because in Simulation Mode with Simple PDU, Packet Tracer sometimes stops after ARP.

Here is why and how to fix:

Why you see only ARP, no ICMP
When Admin 192.168.30.10 pings Student 192.168.10.10 (different subnets):

Admin PC knows 10.10 is not in its own network 30.0
So it does NOT ARP for 10.10. It ARPs for its Gateway 30.1
If the Router's ARP reply is slow in Simulation, the Simple PDU expires before ICMP starts. So you only see ARP.
Your real pings work in Realtime mode because you proved !!!!! 100% — so routing is 100% correct. Simulation is just being picky.

Fix: Use PING in Simulation Mode, not Simple PDU
Don't use Add Simple PDU for inter-VLAN. Use the actual ping command:

Delete all PDUs in Simulation event list
Simulation Mode > Edit Filters > Check only ARP and ICMP (uncheck STP, DTP, everything else)
Keep Simulation Mode running
Click on Admin PC > Go to Desktop > Command Prompt while still in Simulation Mode
Type:
Code
arp -d
ping 192.168.10.10
Now look at the Event List at right - Click Auto Capture / Play repeatedly
You will now see the full flow in order:

ARP Request - Who has 192.168.30.1? Broadcast
ARP Reply - 192.168.30.1 is at Router MAC
ICMP Echo Request - Admin -> Router g0/0/0.30
ICMP Echo Request - Router -> Switch trunk tagged 10 -> Student
ARP Request - Router asks Who has 192.168.10.10?
ARP Reply - Student replies
ICMP Echo Reply - Student -> Router -> Admin
That's 7-8 events. Screenshot that entire event list.

If you still only see ARP:
Click Capture / Forward button manually 1 time at a time instead of Auto Play. Sometimes Auto Play is too fast and skips ICMP.

Do this live:

First packet fails, next 3 succeed. This is NORMAL and expected. Not a bug.

Reason - ARP needs 1 packet time:

Step by step Faculty 20.10 -> Student 10.10:

Faculty PC checks: 10.10 is NOT in my network 20.0/24, so send to Gateway 20.1
Faculty PC checks ARP cache: "Do I know MAC of 20.1?" -> NO, empty at start
Faculty PC sends ARP Broadcast: "Who has 192.168.20.1? Tell 192.168.20.10"
Switch Fa0/2 receives, floods only inside VLAN20
Router g0/0/0.20 replies: "I am 20.1, my MAC is 00:01:..."
This ARP takes time - during this time, the first ICMP packet is dropped -> Request timed out
Now Faculty has MAC of gateway, sends ICMP Echo Request to Router
Router looks at show ip route, sees 10.0/24 is on g0/0/0.10
Router checks its own ARP cache: "Do I know MAC of 10.10?" -> NO again first time
Router sends ARP in VLAN10: "Who has 10.10?"
Student replies with MAC
Router forwards ICMP to Student
Student replies - now all MACs are cached, so next 3 pings succeed instantly
So first packet is sacrificed to learn MAC addresses via ARP.
